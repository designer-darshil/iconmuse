# IconMuse for Figma

Search the IconMuse catalog in Figma Design and insert SVGs as editable vector layers. Search results use small generated token indexes; SVGs are fetched from Cloudflare Workers only for visible previews or when inserted.

## Local setup

1. Install Wrangler and authenticate with Cloudflare (`npm install --global wrangler`, then `wrangler login`).
2. Generate the Worker data: `npm run figma:data`.
3. Start the API: `npm run figma:worker:dev` (local URL: `http://localhost:8787`).
4. Build the plugin: `npm run figma:build`.
5. In Figma Desktop, import `figma-plugin/manifest.json` from **Plugins → Development → Import plugin from manifest…**. This source manifest points into `dist/`, so the plugin code resolves when Figma loads it from the project folder.
6. Search for an icon. Click its tile to add it at the center of the visible canvas.

The source manifest contains a development placeholder plugin ID. Replace its `id` with one generated by Figma before publishing or sharing the built plugin. Rebuild after changing the source manifest. The generated `dist/manifest.json` instead uses paths relative to the `dist/` folder.

## Cloudflare deployment

The Worker serves a metadata search API and lazy SVG shards from its static asset binding. Generate data and deploy with:

```sh
npm run figma:data
npm run figma:worker:deploy
```

Wrangler creates the `iconmuse-figma-api` Worker. Enter the URL shown by Wrangler under **API settings** in the plugin (for example, `https://iconmuse-figma-api.<account>.workers.dev`). Requests are public, read-only GETs and the Worker allows cross-origin plugin requests.

## API

- `GET /api/facets` returns available sources and styles.
- `GET /api/search?q=home&source=Lucide&style=stroke&limit=24&offset=0` returns sorted metadata and a next offset.
- `GET /api/previews?ids=id-one,id-two` returns SVG previews for up to 24 IDs.
- `GET /api/icons/:id` returns the selected SVG markup.

`npm run figma:data` reads the app's generated catalog manifest and compressed shards in `public/`. If the catalog source packages change, run `npm run catalog:build` first. The generated Worker assets are ignored by Git and are rebuilt for every deployment.
